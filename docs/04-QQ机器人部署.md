# 04 · QQ 机器人部署

整套东西由三部分组成：

```
NagCat(Docker) ── OneBot v11 反向 WS ──> NoneBot2(bot.py)
                                            ├─ 素材目录 materials/
                                            ├─ bh2.db（sqlite）
                                            └─ bh2-query（玩家名片，可选）
```

## 1. 机器规格

* 最低 2 核 2G（本项目实测 bot 进程 RSS 约 60 MB，NapCat 占 300–500 MB）
* 素材体积参考：装备卡 2.7 G、立绘 663 M、角色卡 136 M、图标 77 M，
  再加精英技能 / 僵尸娘约 140 M，整体 4 G 左右
* 需要能跑 Chrome/Chromium 时（出图功能）额外 ~300 MB

## 2. NapCat（QQ 网关）

Docker 起，扫码登录一次，之后可保存登录态：

```bash
docker run -d --name napcat --restart=always \
  -e NAPCAT_UID=1000 -e NAPCAT_GID=1000 \
  -p 3000:3000 -p 6099:6099 \
  -v /opt/napcat/config:/app/napcat/config \
  -v /opt/napcat/qq:/app/.config/QQ \
  mlikiowa/napcat-docker:latest
```

配置里开反向 WS 到 `ws://127.0.0.1:8080/onebot/v11/ws`，
token 与 `.env` 的 `ACCESS_TOKEN` 保持一致。

> 同一 QQ 号只能在一处在线：本地调试时记得先停掉云端的 NapCat，
> 否则两边互相顶号。

## 3. 部署 bot

```bash
sudo mkdir -p /opt/bh2-bot && sudo chown $USER /opt/bh2-bot
git clone <this repo> /opt/bh2-bot
cd /opt/bh2-bot
python3 -m venv venv && venv/bin/pip install -U pip
venv/bin/pip install -r requirements.txt
cp .env.example .env       # 填 ACCESS_TOKEN / BOT_ADMINS / MATERIAL_ROOT
```

把素材放到 `MATERIAL_ROOT`（默认 `./materials`），结构见 `03-卡面与素材制作.md`。

先把数据库表建好（各插件首次加载会自动建表，也可以手动跑一次）：

```bash
venv/bin/python bot.py     # 前台跑一次，确认所有插件 Succeeded to load
```

Systemd：

```bash
sudo cp deploy/bh2-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now bh2-bot
journalctl -u bh2-bot -f
```

## 4. 插件与命令

| 插件 | 命令 | 说明 |
|---|---|---|
| `equip_query` | `装备查询 <名称/ID>` | 出装备卡 + 技能/觉醒信息 |
| `illust_query` | `立绘查询` / `CG` / `壁纸` | 觉醒立绘、角色立绘、官网 CG 浏览 |
| `chara_query` | `查询角色` / `角色语音 <名> [中文\|日文]` | 角色卡与语音 |
| `guess_game` | `猜装备` / `猜装备排行榜` | 看剪影猜装备 |
| `wife` | `抽老婆` / `换老婆` | 每日抽卡（管理员不限次） |
| `emote` | `表情包` | 随机表情 |
| `announce` | `开启公告` / `关闭公告` | B 站动态推送（含新鲜度护栏） |
| `official_news` | `开启官网公告` / `关闭官网公告` | 官网公告推送 |
| `auto_reply` | `新增回复` / `新增全局回复` / `修改回复` / `删除回复` / `查询回复` | 群内固定回复 |
| `module_switch` | `开启功能` / `关闭功能` / `功能列表` | 群级功能开关 |
| `elite_skill` | `精英技能` / `查询技能 <名或编号>` | 58 项技能汇总图 + 单卡 + 动图 |
| `zombie` | `僵尸娘` / `查询怪物 <名或 NO.xx>` | 58 只僵尸娘汇总图 + 资料卡 + 合并动图 |
| `dragon` | `群龙王` | 本周群发言榜（周日 22:00 自动推） |
| `player_query` | `查询玩家 <uid>` / `查询b2玩家 <uid>` / `查询官服玩家 <uid>` / `绑定玩家` / `查询自己` / `查询@某人` | 玩家名片（需 bh2-query，见 05） |
| `guard_alert` | `守护状态` | NapCat 掉线告警与最近事件 |

所有命令前缀为空（`COMMAND_START=[""]`），直接说「查询装备 轰击晨星」即可。

## 5. NapCat 守护

`deploy/napcat-guard.sh` 三路检测（容器 / QQ 进程 / 6099 端口），
异常时 `docker restart napcat`，5 分钟冷却，恢复后把掉线时长写进
`/var/log/napcat-guard/pending.jsonl`，由 `guard_alert` 私聊推给管理员。

```bash
sudo cp deploy/napcat-guard.sh /usr/local/bin/ && sudo chmod +x /usr/local/bin/napcat-guard.sh
sudo cp deploy/napcat-guard.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now napcat-guard
```

> 有的账号重启 NapCat 后需要重新扫码，那就把脚本里的 `docker restart`
> 换成「只写告警」，别让守护把自己锁在需要人工扫码的状态。

## 6. 素材与数据库

* `materials/` —— 只读素材，可直接从本地同步（`rsync -a --delete`）
* `bh2.db` —— sqlite，记录装备索引、猜装备排行、群开关、推送去重、
  龙王榜统计、玩家绑定等；**定期备份**，它不能从素材重建

## 7. 出图依赖

出图用 headless Chrome/Edge：

```bash
sudo apt install -y chromium-browser fonts-wqy-zenhei fonts-noto-cjk
```

字体很关键：没有中文字体时卡面会变成方框。`paths.FONT_BD` 会自动找
`msyh*` / `wqy-zenhei` / `Noto Sans CJK`。
