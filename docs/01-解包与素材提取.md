# 01 · 解包与素材提取

目标：从官方 APK / 客户端资源里拿到

* 配置表（TSV）——装备、技能、使魔、徽章、角色、文本
* 图片素材——装备图标、觉醒立绘、表情差分、萌章、服装拆件图集、技能演示

> 这些脚本只处理**你自己设备上已安装的客户端文件**，请遵守游戏用户协议，
> 不要分发游戏原始资源。

## 0. 依赖

```bash
pip install UnityPy==1.20.10 pycryptodome lz4 pillow openpyxl
```

## 1. 从 APK 里取出 AssetBundle

```bash
python unpack/apk_extract.py            # 默认读 $BH2_DATA/apk/bh2.apk
```

脚本会把 APK 里 `assets/` 下的 `*.unity3d` / `*_<40位hex>` 解到
`data/apk/`。装饰包（menusv2、character、inlevel 等）文件名带逻辑名，
剩下大量 `assetbundle__<数字>_<hash>` 是无逻辑名的，只能靠内容判断。

真机 / 模拟器上的**热更资源**在

```
/sdcard/Android/data/<包名>/files/Res/AssetBundles/
```

用 `adb pull` 整目录拉下来即可（本项目实测 2600+ 个包、约 4.7 GB）。

## 2. 13.4 之后的资源包要过 GGZV2

13.4 起数据块不再是裸 LZ4，而是「AES-CBC 密文 + 16 字节尾」，
IV 由尾部 16 字节与固定表异或得到。两种用法：

**做法 A：整包改写成明文包（本项目主流程）**

`unpack/unpack_assets.py` 会按 GGZV2 把每个块的密文解开、再重新拼回一个
块信息明文的 UnityFS，写进 `data/packs_dec/`。之后所有 `export_*.py`
读的都是这份明文包，不再关心加密：

```bash
python unpack/unpack_assets.py data/raw/data_all.unity3d   # 单文件
python unpack/unpack_assets.py data/dev_bundles            # 或整个目录
# 输出：data/packs_dec/*.unity3d（UnityPy 可直接读）
```

**做法 B：挂进 UnityPy 的解压表（临时看一眼时方便）**

```python
import gzzv2
gzzv2.install()          # 把 LZ4/LZ4HC 的解压函数换成 GGZV2 版本
import UnityPy
env = UnityPy.load("some_bundle.unity3d")
```

算法来源是社区（Modder4869 / StudioDev 的 `BundleFile.cs` 等）的整理，
本项目只做 Python 侧适配与封装。13.4 之前的版本仍是裸 LZ4，不需要这一步。

## 3. 主数据包：data_all.unity3d

`data_all_<hash>.unity3d` 里是全部 TextAsset（配置表）与部分纹理。

```bash
python unpack/unpack_assets.py data/raw/data_all.unity3d   # 先转明文包 -> data/packs_dec/
python unpack/export_tables.py                             # 再解 TextAsset -> data/tsv_all/
```

* `export_tables.py` 只把 `TextAsset` 落成 `.txt`，一张表一个文件，
  13.4.8 实测 **14671 张**表（含 textmap 分片）；
* `unpack/bundle_decrypt.py` 是**13.4.1 及更早**的旧方案（整包 AES-256-CBC +
  逐块 AES：key `LPC@a*&^b19b61l/`、iv 全 0 + LZ4HC）。13.4.8 换了 key，
  在新包上跑只会得到乱码头，**不要用**。

> UnityFS 的 block 信息里，`blocksInfo` 是明文 LZ4，数据块才是密文。
> 如果解出来报 `LZ4 decompress failed: error code 110`，就是漏了块解密。

## 4. 图片素材

| 素材 | 脚本 | 说明 |
|---|---|---|
| 装备图标 | `export_textures.py` | alias/图标集，失败时回落到官方 CDN（见下） |
| 觉醒立绘 | `export_figures.py` | 贴图名 = FigureID；同名多份时优先 1024×1024 |
| 表情差分 | `export_faces.py` | `menusv2_partner_allpartnerfigures_partner<NNN>` 里的 256×256 |
| 服装拆件图集 | `export_costume_atlas.py` | `character_player_costumedata` 里 612 张整图 + `.atlas` |

几个踩过的坑：

1. **贴图名不等于装备 ID。** 觉醒立绘的贴图文件名是 `FigureID`，
   而配置表里给的是 `PosterID`，两者差 1000（`PosterID 1202 → FigureID 2202`），
   映射表在 `tsv_all/partnerposterdata.txt`。
2. **无逻辑名的包只能靠贴图名找。** 例如萌章图集在
   `menusv2_vip_vipframebadge_*`，包名里没有 "emblem" 字样。
3. **图集贴图名是 0 基，配置表 ID 是 1 基**（萌章少 1），取图时要减一。
4. **服装图集不要硬切单件。** 同一图集里不同 region 的坐标约定不一致
   （有的左上原点、有的左下原点、有的宽高互换），硬切会串到邻件；
   需要单件时按 `.atlas` 里的 region 与 Spine 骨架槽位还原。

## 5. 官方静态 CDN（缺图时的兜底）

```
装备图标   http://static.image.mihoyo.com/hsod2_webview/images/broadcast_top/equip_icon/png/<id>.png
萌章图标   http://static.image.mihoyo.com/hsod2_webview/images/broadcast_top/emblem_icon/<DisplayImage>.png
精英技能   http://static.image.mihoyo.com/hsod2_webview/images/broadcast_top/map_icon/picture/properties/0NN.png
```

图标是 128×128，带紫/橙底，和图鉴里用的一致。CDN 只覆盖已公开的资源，
新上架（未到开放时间）的条目会 404。

## 6. 抓包（可选，只用于协议研究）

```bash
adb shell "su -c 'tcpdump -i any -n -s 0 -U -w /sdcard/cap.pcap tcp and not port 443'"
adb pull /sdcard/cap.pcap
python unpack/pcap_scan.py cap.pcap --dump <端口>
```

`pcap_scan.py` 不依赖 scapy，纯标准库解析 pcap/pcapng，可以按连接
导出上行/下行字节流。参数与用途见 `05-玩家名片协议.md`。
