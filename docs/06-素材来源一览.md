# 06 · 素材来源一览

机器人用到的每一份素材，来源只有四类。**没有任何一份是从别人的整合包里搬来的**，
要么自己解包、要么自己抓官网、要么自己渲染、要么自己整理。

| 类别 | 说明 | 是否可复现 |
|---|---|---|
| A 客户端解包 | 需要你自己设备上装的客户端（或 APK） | 可以，见 [01](01-解包与素材提取.md) |
| B 官网抓取 | 官网公开页面/公开接口，不需要装游戏 | 可以，见本文第 1、2 节 |
| C 本地渲染 | 用上面两类素材 + 配置表渲染出的卡面 | 可以，见 [03](03-卡面与素材制作.md) |
| D 手工整理 | 逐张人工挑选/截图/录入 | 部分可以，见第 5 节 |

## 1. 官网「角色板块」→ 角色卡（26 位）

角色卡不是解包做的，资源全部来自官网首页：

```
1) 首页 https://www.benghuai.com/             ← 拿到 26 个角色的 id
2) 资源目录 https://static-event.benghuai.com/new_mihoyo_homepage/chara/{id}/
     role.png      角色立绘（透明 PNG）
     info.png      角色档案图（CV / 生日 / 年龄 / 身高 / 体重 / 三围）
     title.png     角色名标题图
     voice/china/001~005.mp3   中文语音
     voice/japan/001~005.mp3   日文语音
```

`cards/build_chara_cards.py` 会按上面的规则批量下载、拼装、截图：

```bash
python cards/build_chara_cards.py            # 全部 26 位
python cards/build_chara_cards.py kiana      # 单张
```

### 为什么每张角色卡的 HTML 不一样

这一点必须说清楚：**不是一套模板套 26 个**。官网立绘的构图、朝向、留白差别很大，
直接套模板会出现「人物压住文字」「人物偏在角落」「标题压到头发上」这类问题，
所以脚本里对每个角色做了逐项调整：

| 调整项 | 作用 |
|---|---|
| `MIRROR_IDS` | 官网角色按顺序**奇偶交替**排布（一个在右、一个在左）。偶数位角色的立绘要水平镜像，人物才朝卡片内侧看 |
| `SHIFT_RIGHT` | 14 个角色立绘整体右移约 10% 卡片宽（超出部分 `overflow:hidden` 裁掉），给左侧文字让位 |
| `SHIFT_EXTRA` | 在 10% 基础上再叠加：阿库莉亚 +25%、诗音 +20%、蒂亚拉 +10% |
| `PROFILES` | 每个角色的 CV、生日、年龄、身高、体重、三围 —— 从官网 `info.png` **逐张人工读取录入** |
| `VOICE_COUNT` | 每个角色中/日各 5 条语音，卡片里按编号列出 |

所以如果你只换角色 ID 而不调这些参数，出来的卡会很别扭。想加新角色，
照着 `ROLES` 里已有的条目补一条，再按上面四项各调一遍。

## 2. 官网下载页 → 表情包（`.eif`）与 CG

下载页是 <https://www.benghuai.com/download/>，页面上有四个下载区：客户端、CG、表情包、输入法皮肤。

### 表情包是 `.eif`，其实是 OLE2 复合文档

「表情包」区每一套下载下来是一个 `.eif` 文件，它**不是图片**，而是
**OLE2 复合文档**（Compound File Binary Format，和老的 `.doc`/`.xls` 同一个容器格式）。
里面按流存放着这一套表情的 PNG，所以直接用看图软件打不开。

解出来的两种办法：

```bash
# 方法一：7-Zip 直接打开（能看到里面的 stream，逐个提取）
7z l  琪亚娜四格表情.eif
7z x  琪亚娜四格表情.eif -o./琪亚娜四格表情

# 方法二：Python olefile（推荐，能按名字精确取流）
pip install olefile
python - <<'PY'
import olefile
ole = olefile.OleFileIO('琪亚娜四格表情.eif')
for entry in ole.listdir():
    name = '/'.join(entry)
    data = ole.openstream(entry).read()
    open(name.replace('/', '_'), 'wb').write(data)
PY
```

**每个 `.eif` 里同一张表情通常有「大图 + 小图」两份内容一样的文件**，
本项目只保留大图，所以最终整理出来的 433 张并不是原始流数量。

17 套的目录结构（括号里是保留的大图张数）：

### CG 下载区

页面上的 CG 区是前端渲染的，清单在
`https://static-event.benghuai.com/new_mihoyo_homepage/config/config.js`
里的 `download_cg_list`（`[文件名, 标题, 备用]`），原图地址为：

```
https://static-event.benghuai.com/new_mihoyo_homepage/images/download/cg/origin/<文件名>
```

13.4.8 时共 142 张（2014-07-25 ~ 2024-03-05），下载后统一转 progressive JPEG
（长边 ≤1920，q=90）能把 198 MB 压到 72 MB。机器人里搜 `cg` / `壁纸` 即可浏览。

## 3. 设备热更目录：把「没随包下发」的立绘捞回来

**什么时候用**：某个装备已经有觉醒素材表（`personatedata` 里能查到材料与开放时间），
但 `觉醒立绘/` 里找不到对应大图 —— 说明这张图没进 APK，而是热更时才下发的。

### 3.1 先确认素材表在、只是图不在

```bash
# 图鉴表里 立绘ID → partnerposterdata 的 FigureID（两者差 1000）
grep -P "^\d+\t" data/tsv_all/partnerposterdata.txt | head
ls materials/觉醒立绘/<FigureID>_*.png        # 空 = 图缺
```

如果 `partnerposterdata` 那一行是占坑行（`PosterName` 指向
`看板No.xxxx Name`、`Group=99999`），那说明**官方自己也还没把资料填完**，
这种情况等版本更新即可，不必折腾。

### 3.2 把设备的资源目录整包拉回来

客户端运行时读的不是 APK 里的 `assets`，而是解包后落到外部存储的热更目录：

```
/sdcard/Android/data/<包名>/files/Res/AssetBundles/*.unity3d
```

13.4.8 实测有 **2681 个包、约 4.7 GB**。整目录拉回来：

```bash
adb -s emulator-5554 shell "ls /sdcard/Android/data/<包名>/files/Res/AssetBundles | wc -l"
adb -s emulator-5554 pull /sdcard/Android/data/<包名>/files/Res/AssetBundles ./dev_bundles
```

> 包名：国服 `com.miHoYo.HSoDv2Original`，B 服 `com.miHoYo.HSoDv2BiliBiliRelease`。

### 3.3 按贴图名扫 FigureID

热更包里大部分是**无逻辑名**的 `assetbundle__<数字>_<40位哈希>.unity3d`，
所以不能靠包名找，只能进包里看**贴图名**——热更包的贴图名就是 FigureID 字符串：

```python
import UnityPy
for path in bundle_dir.glob('*.unity3d'):
    env = UnityPy.load(str(path))
    for obj in env.objects:
        if obj.type.name != 'Texture2D':
            continue
        d = obj.read()
        if str(d.m_Name) == str(figure_id):
            ...  # 命中：注意同一 ID 可能有多份
```

两个必须处理的坑：

1. **同一 FigureID 可能命中多份**（2048 的拆件图集里也有同名贴图）。
   优先取接近 1024×1024 的那张，否则取面积最小的；
2. **一次只扫一个 FigureID 会很慢**（2681 个包），实际做法是
   「一次遍历，把所有目标的 FigureID 都记下来」，再按需导出。

本项目用这个办法给 55 个缺失的 FigureID 找回了 **54 张**大图，
唯一没找到的是 `2202`（丧恸哀光）——它的立绘当时确实还没下发，
等它开放后再跑一次即可。

### 3.4 想确认「现在界面上这张图是哪个包」

不用猜，直接看进程打开了什么文件：

```bash
adb shell "su -c 'ls -l /proc/<pid>/fd | grep unity3d'"
```

配合 0.05 秒轮询、进出某个界面，就能把「这个页面加载了哪些包」抓全。
萌章图集（`menusv2_vip_vipframebadge`）就是这样定位到的 —— 包名里根本没有 "emblem" 字样。

## 4. 官网数据站 → 精英技能 / 僵尸娘

数据站 <https://www.benghuai.com/data/> 的「精英技能」「僵尸娘」两个专栏，
页面前端统一调一个接口：

```
POST https://www.benghuai.com/data/getData
     type=elite_skill|zombie & page_num=1 & page_size=500
POST https://www.benghuai.com/data/getDataByID?id=<id>&type=zombie      # 详情
```

图标与演示图在 `static.image.mihoyo.com/.../map_icon/...` 下。注意详情里的图片路径
用的是**反斜杠且带空格/中文**（`...\Attack_mode\1070 - 鲨鱼娘 - 01.gif`），
下载前必须转成正斜杠再 `urllib.parse.quote()`，否则会报
`InvalidURL: URL can't contain control characters`。

具体渲染与合并动图参数见 [03](03-卡面与素材制作.md)。

## 5. 手工整理 / 需要自己找的素材

| 素材 | 说明 |
|---|---|
| `词条图标/`（45 张） | 使魔词条图标**在客户端里没有找到独立资源**（图集、`assets/bin/Data`、运行时目录都翻过）。做法是：在游戏内打开「使魔 → 词条」界面，逐条**截图**，再抠图——先合成到白底避免透明区变黑，按饱和色块算外接矩形裁成正方形，最后用颜色键去白底，输出 256×256 透明 PNG。1~13 号老词条在官网 CDN 有一份旧版美术，但与现行客户端不是一个画风，已弃用 |
| `固定回复/`（8 张） | 机器人 `新增回复` 功能的配图，**自行去米游社找最新的攻略图**即可，不影响任何解包/抓取流程 |

这两项都不是脚本批量产出的，别人复现要自己动手。

## 6. 运行时才抓的图（不在上面这些目录里）

| 内容 | 来源 | 说明 |
|---|---|---|
| 群龙王榜头像 | `https://q1.qlogo.cn/g?b=qq&nk=<QQ>&s=100` | 腾讯公开头像接口，按 QQ 号取 100×100；抓过一次就缓存在 `龙王榜/avatars/`，不重复请求 |

| B 站动态 | `https://api.bilibili.com/x/polymer/web-dynamic/v1/opus/feed/space` 等 | 灵依娘（mid `133934`）动态，需要 Cookie 时在 `.env` 配 |

## 7. 一句话总结

```
配置表与大部分美术  → 自己解包（unpack/）
热更才有的立绘      → 从设备 Res/AssetBundles 整包捞（本文第 3 节）
官网能查到的资料    → 自己抓（cards/ 里的 build_* 脚本）
卡面与名片          → 本地渲染（cards/ + bot/src/plugins/player/card.py）
词条图标、固定回复  → 自己在游戏内截图 / 去米游社找（本文第 5 节）
```
