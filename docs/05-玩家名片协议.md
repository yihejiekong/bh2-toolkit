# 05 · 玩家名片：自己实现游戏协议

游戏内的「玩家搜索 → 名片」不是 HTTP 接口，而是 **TCP 私有协议 + 自定义二进制**。
本仓库把「登录、查名片」这一段用纯 Python 复现了，不需要模拟器也不需要客户端。

> ⚠️ 先读这一段
>
> * 协议里的**登录帧就是你的账号凭据**。任何情况下不要把 `servers.json`
>   或抓包文件提交到仓库、发到群里、贴到 issue。
> * 用脚本登录会把**你自己正在玩的设备顶下线**，并且属于非正常客户端行为，
>   有触发风控 / 封号的风险。请只用小号、只在需要时连接。
> * 本项目只在「查自己账号可见的公开资料」范围内使用，请自行承担合规风险。

## 1. 帧格式

```
[4B 大端总长(含自身)] [30B 头] [8B 尾] [载荷]
头 = cmd:u16 | 0xea60:u16 | 00000000 | 会话号(4B) | 14B 零
尾 = 时间戳:u32 | 校验:u32
```

* 时间戳 = `unix 秒 + 2006083400`，服务器只要求「不太离谱」，实测 ±60 秒都能过；
* 校验 = `~CRC32_reflected(poly=0xEDB88321, init=0x5E0600BE)`，
  输入是**帧前 30 字节 + 8 个 0 + 载荷**（不是裸载荷，这一点踩了很久）；
* 改任何一个字节都要重算校验，否则服务器**静默丢包**（不报错，就是不回）。

实现见 `bot/src/plugins/player/proto.py`。

## 2. 用到的命令

| 方向 | cmd | 载荷 | 说明 |
|---|---|---|---|
| ↑ | `0x0001` | 登录帧 | 登录，回 `0x0300` ack + 大量世界同步帧 |
| ↑ | `0x2410`×6 / `0x0023` / `0x0046` / `0x0063` | 见 `_PRIME_TAIL` | 登录后的初始化序列 |
| ↑ | `0x0005` | `own_uid(4B) + 会话累计秒数(4B)` | 心跳，约 15 秒一次 |
| ↑ | `0x0029` | `own_uid + 目标uid + 00` | 名片摘要请求 |
| ↓ | `0x002a` | — | 摘要：等级 / VIP / 公会 / 昵称 |
| ↑ | `0x02b2` | `own_uid + 目标uid` | 名片详情请求 |
| ↓ | `0x02b3` | — | 详情：展示栏 5 个列表 + 金银铜成就 + 角色 + 看板/萌章数 + 履历 |

摘要（`0x002a`）只给昵称、等级、VIP、公会；**看板数、萌章数、成就数、
展示装备、履历全在 `0x02b3` 里**，必须再发一次 `0x02b2`。

## 3. 自己抓参数（必须做一遍）

1. 装一个能 root 的模拟器（本项目用 MuMu），装游戏、登录小号；
2. 抓包：

```bash
adb shell "su -c 'nohup tcpdump -i any -n -s 0 -U -w /sdcard/login.pcap tcp and not port 443 &'"
# 启动游戏，等它进到主界面
adb shell "su -c 'pkill -f tcpdump'"
adb pull /sdcard/login.pcap
```

3. 解析：

```bash
python unpack/pcap_scan.py login.pcap --dump 26001
```

   会打印出每个连接的上行/下行字节流；网关端口通常是 `26001`。

4. 从上行第一帧取 4 个参数：

| 参数 | 从哪来 |
|---|---|
| `host` | 抓包里的对端地址（`/proc/net/tcp` 里看得到真实网关） |
| `session` | 帧头第 12–16 字节（同一会话内不变） |
| `own_uid` | 帧头里那 4 字节「客户端常量」，B服常见 `0x0001A407`，官服 `0x0001A408` |
| `login_hex` | 整个登录帧（`0x0001` 那帧）的十六进制 |

5. 写进 `servers.json`（**不要提交**，已在 `.gitignore`）：

```json
{
  "b2": {
    "name": "B服",
    "host": "<网关地址>",
    "session": "<8 位十六进制>",
    "own_uid": "0x0001A407",
    "login_hex": "<登录帧十六进制>"
  }
}
```

登录帧有有效期（换号/长时间不用会失效），失效后重抓一次即可。

## 4. 常驻查询服务

`bot/src/plugins/player/service.py` 为每个区服保持一条已登录连接，
对外只有两个 HTTP 接口（默认 `127.0.0.1:8791`，别暴露到公网）：

```
GET /status                      -> 各区服连接状态
GET /pull?uid=<uid>&srv=b2       -> {"ok":1,"sum":"<hex>","det":"<hex>"}
```

**登录只在启动和断线时做一次**，查询复用同一条连接 —— 每次查询都重新登录
既慢又容易被风控。心跳必须发 `0x0005`（`0x0046` 是登录后一次性的初始化帧，
拿它当心跳会 50 秒掉线）。

```bash
sudo cp deploy/bh2-query.service /etc/systemd/system/
sudo systemctl enable --now bh2-query
curl -s 127.0.0.1:8791/status
```

## 5. 载荷解析

`bot/src/plugins/player/parse.py`：

* `parse_summary` —— 头部定长字段 + 顺序「u16 长度 + UTF-8」字符串（先公会后昵称）；
* `parse_detail` —— 5 个展示列表（`u8 count + count×u16`），
  之后是金银铜成就（3×u32），再是履历区，最后是角色列表 + 看板/萌章/隐藏数；
* 履历不是定长，20–28 字节都出现过，用 DP「恰好铺满整个履历区」的方式切分，
  铺不满就当没有（盲扫会在尾部随机字节上拼出假记录）。

离线/精简名片只有 150 字节左右，展示栏全空，解析要能容忍。

## 6. 能拿到什么

已经验证可以稳定取出：

* 昵称 / UID / 等级 / VIP / 公会
* 游戏时长（秒）、注册时间
* 收藏数：拥有角色数、看板数、萌章数
* 成就：金 / 银 / 铜
* 展示武器 / 服装 / 使魔 / 徽章各最多 10 个（含 ID，可映射成名称与图标）
* 展示萌章（10 枚）
* 对外展示的履历（里世界名次、阵营战等，含名次与时间）

拿不到的：装备词条、具体数值、未展示的收藏明细 —— 这些客户端不上行。
